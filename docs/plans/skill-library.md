# 中央 Skill 库与本地导入（P25）

本文记录阶段 F 首个任务（P25「登记中央 Skill 来源」）的设计、边界与实际验证方式。
安装、更新与向 Agent 部署属于后续任务，本文不提前承诺。

## 目标与范围

- 导入用户已有的本地 Skill 目录（含 `SKILL.md` 的目录），登记为中央库条目。
- 中央库存放受管副本，原目录不移动、不修改、不删除。
- 记录稳定 ID、内容摘要、来源路径、可补充的上游来源与 revision。
- 列表有界分页；无法识别上游来源时明确显示为不可自动更新。

P25 不实现：从 GitHub/npx 获取、更新检查与差异、向 Agent 部署、删除、原生目录选择器。

## 数据模型（schema v10）

`skill` 表保存元数据，内容文件保存在应用数据目录的 `skills/<id>/`。

| 字段                             | 说明                                         |
| -------------------------------- | -------------------------------------------- |
| `id`                             | 32 位小写十六进制随机 ID，同时是受管目录名   |
| `name`                           | Skill 名称，1–64 字符，库内唯一              |
| `description`                    | 来自 frontmatter，1–1024 字符                |
| `origin_path`                    | 导入时的本地来源目录（绝对路径，已规范化）   |
| `source_url` / `source_revision` | 用户补充的上游来源与版本；未填写表示来源未知 |
| `content_digest`                 | 导入内容的 SHA-256 十六进制摘要              |
| `file_count` / `byte_size`       | 受管副本的文件数与字节数，用于显示与边界校验 |
| `revision`                       | 元数据修订号，来源补充时递增，防止并发覆盖   |
| `imported_at` / `updated_at`     | Unix 毫秒时间戳                              |

约束 `origin_path IS NOT NULL OR source_url IS NOT NULL` 保证每条记录至少有一个可解释的来源：
P25 的导入总是写入 `origin_path`，`source_url` 由用户另行补充。

### 内容摘要定义

摘要按排序后的相对路径逐一写入 SHA-256，前缀为版本标记，避免路径与内容边界歧义：

```text
"vibemate-skill-v1\0"
每个文件: u64_be(路径字节长度) + 路径 + u64_be(内容长度) + 内容
```

相对路径用 `/` 连接，保证同一目录在 macOS/Windows/Linux 得到相同摘要。

### 未知来源语义

本地导入只说明内容来自哪个目录，不说明上游仓库。界面据此显示：

- 已填写 `source_url`：显示来源地址与 revision，并注明自动更新尚未实现。
- 未填写：显示「来源未知，不可自动更新」，并提供补充来源的操作。

不从目录名推断 GitHub 仓库或安装器，也不在导入时读取 `.git` 配置。

## 界面

- 列表只保留一行技能的关键信息：名称、最多两行的描述（超出用省略号截断）与来源状态；
  文件数、大小、摘要、路径与时间都放在详情页，避免卡片过高。
- 页头下方、列表上方显示库内总量（「共 N 个技能」），数字来自分页响应的 `total`，
  因此不受已加载页数影响；为 0 时不显示该行，只保留空状态说明。
- 详情页展示用户可读的事实（名称、描述、文件数、大小、导入路径、来源、导入与
  最近修改时间），并在同一页编辑上游来源地址与 revision（保存、并发与未知结果处理
  与列表共用同一套错误码）。事实卡片与来源卡片用与 Agent 详情页相同的 10px 卡片间距。
- 内容摘要不进入界面：它是机器比对用的值，普通用户无法据此判断任何事；仍然记录在库中
  作为后续变更检测与更新比较的基线（P29）。
- 列表页的「详情」按钮先重新读取该技能（`get_skill`），保证编辑基于最新 revision。

### 来源语义

「来源」表示内容从哪里来，界面据此显示三种情况：

- 已记录来源地址（未来从 skills.sh 等位置下载安装时由安装流程写入）→ 显示该地址，
  列表行同时显示 revision。
- 仅本地导入目录（P25 的全部记录）→ 显示「本地导入」，列表行显示「来源：本地导入」。
- 两者都没有 → 显示「未知」（当前校验要求至少有一个来源，因此不会出现）。

「不可自动更新」不再挂在来源行上：更新能力是全局状态，由详情页与列表页的能力说明
（「自动更新与向 Agent 部署尚未实现。」）统一表达。

### 更新路径（已确认：路线 A）

更新能力的判定条件是「来源是否明确」，不是「是否由 vibemate 安装」：本地导入的技能只要补齐
来源地址与**获取方式**，就与下载安装的技能走同一条流程（P29 三方比较 → P30 应用）。这与
`development-plan.md` 已把「安装方式」列入中央目录组成部分的描述一致。

现状与前提：`skill` 表已有 `source_url` 与 `source_revision`，但**没有**获取方式字段，所以
现在填写地址只产生记录与展示效果。获取方式的契约由 BR9 定义，字段随 P26 的「成功记录来源及
可更新方式」写入（一次 `ALTER TABLE` 迁移），届时本地导入的技能在来源页补齐地址与获取方式后
即可检查更新。

若 BR9 之后改变该决定（例如限定只有 vibemate 安装的技能可更新），界面必须同步说明，不能保留
「填了地址即可更新」的暗示。

## 导入流程

用户点击「本地导入」，由 Rust 打开系统文件夹选择器（`tauri-plugin-dialog`），再导入所选目录：

1. 校验路径字符串（绝对路径、长度、无控制字符），规范化后要求是目录，且不在中央库目录内。
2. 发现候选：所选目录本身含 `SKILL.md` 时只导入它；否则取它的直接子目录中含 `SKILL.md` 的那些，按名称排序。
3. 每个候选：读取并解析 `SKILL.md` 的 YAML frontmatter，取出 `name` 与 `description`；其他键忽略。
4. 有界遍历源目录，生成待复制文件清单（相对路径、大小），拒绝符号链接与特殊文件。
5. 复制到 `skills/.import-<random>/`，同时计算摘要与字节数；发现源文件在遍历后变化则整体失败。
6. 原子改名为 `skills/<id>/`，再在单个事务中写入数据库行（库内同名校验）。
7. 数据库失败时删除受管副本；删除失败返回 `outcome_unknown`，要求重新加载后确认。

一个候选失败不影响其他候选：命令返回 `imported` 与 `skipped`（文件夹名 + 安全原因码），界面显示
导入数量与被跳过的文件夹及原因。关闭选择器不是错误，也不会改动任何内容。
导入不会执行 Skill 中的任何命令，也不会读取 Skill 之外的文件。

## 边界与限制

- 文件名与目录名：单段 1–128 字节，总相对路径 ≤ 512 字节，深度 ≤ 16。
- 单文件 ≤ 16 MiB，总字节 ≤ 64 MiB，文件数 ≤ 2048（已发布的技能通常有数百个示例/
  测试文件，实际样本约 11 MiB / 315 个文件；上限同时写在 `skill` 表约束和前端响应校验里）。
- frontmatter 块 ≤ 64 KiB：限制只作用于 YAML 头部，`SKILL.md` 正文可以很长
  （实际样本约 87 KiB，只读取到结束标记为止）。
- 跳过任何层级的 `.git`（含 gitfile），不复制版本库元数据。
- 符号链接与 FIFO/设备文件一律拒绝，不跟随、不解引用。
- 库内同名（`name` 相同）导入返回 `name_taken`；替换与更新流程留给 P26/P29。
- 上限调整需要迁移（v11 重建 `skill` 表以放宽 CHECK）；已应用的迁移不修改。
- 一次选择最多导入 64 个技能文件夹；超限返回 `source_too_large`，需分批导入。
- 发现只向下看一层：所选目录或它的直接子目录，不递归搜索更深的层级。
- 所选目录本身含 `SKILL.md` 时只导入它，不会同时导入它的兄弟技能目录。

## 系统选择器与权限

- 选择器由 Rust 通过 `tauri-plugin-dialog` 2.8.2 打开（`blocking_pick_folder`，在
  `spawn_blocking` 线程调用，主线程只负责显示）。弹窗归属主窗口，取消视为正常结果。
- 前端从不调用插件自身的 IPC 命令，因此没有新增 capability 权限；插件的传递依赖
  `tauri-plugin-fs` 未被注册，也没有任何 `fs` 权限。

## 未实现与已知缺口

- 本地修改检测：导入摘要即基线，差异比较随 P29 的三方内容比较实现。
- 删除、替换、重新导入现有条目。
- 选择器内的默认目录、多选与最近使用记录。
- 内容摘要当前不包含文件权限位。
- 获取方式字段缺失：更新链路的前提，随 P26/BR9 引入（见「更新路径（已确认：路线 A）」）。

## 证据

- 本机 `~/.grok/skills/`、`~/.agents/skills/` 样本确认目录结构为含 `SKILL.md`
  的目录，frontmatter 使用 `name` 与 `description`，并允许 `license`、`metadata`、
  `disable-model-invocation` 等额外键。
- `docs/integrations/pi.md`、`docs/integrations/grok-build.md` 记录的目录约定用于
  校验规则；部署阶段的 Agent 专用规则仍以 P27/P28 的再次核实为准。
